# iPhone Safari の画面回転後のタイル選択（2026-10-08）

## 調査結果

- 当たり判定はイベントごとに `getBoundingClientRect()` を読み、表示座標を固定サイズの盤面座標へ変換する。回転・反転・拡大縮小の逆変換後、元画像のアルファ値を調べる。古い表示サイズをキャッシュする実装ではない。
- 修正前は `drag` が存在すると新しい `pointerdown` をすべて無視していた。終了イベントを取り逃した場合に入力を再開できず、画面回転・フォーカス喪失に対する解除処理もなかった。
- 「次のタイルを選択」は未反映の色変更を確定し、`selected` を次のIDへ変更、操作ボタン・選択表示を更新し、再描画を予約する。画像のアルファ値、当たり判定の式、タイル位置、ドラッグ状態は変更しない。そのため、残留ドラッグだけでは、このボタンで復帰するという実機の報告を説明できない。回転後の描画更新に関する可能性も残る。
- iPhone Safari の実機で現象を再現できておらず、実際の原因は未確定。今回の修正は確認できた復帰処理の欠落と、回転後の再描画不足への対応。

## 修正

GitHub Pages版 `app.js` と GAS版 `gas/index.html` に同じ修正を適用。

- リサイズ・画面回転時に進行中のドラッグとポインターキャプチャを解除し、requestAnimationFrameで再描画する。選択対象・配置・画像・色は保持する。
- 新しい主ポインターの押下で古いドラッグを解除し、新しい操作として処理する。第2指の入力は従来どおり無視する。
- フォーカス喪失、ページ非表示時にもドラッグを解除。ページ再表示時は再描画。
- 盤面外へ届いた pointerup / pointercancel でもドラッグを終了する。
- リセットも共通のドラッグ解除を使用する。
- レイアウト・ボタン・当たり判定式・画像処理は変更していない。旧GAS版は変更していない。

## テスト

Chromeのモバイル・タッチ設定で `tests/orientation.cjs` を実施（両版成功）。

- 縦390×844 / 横844×390の切り替えを6回実行。
- 回転・反転・色変更したタイルをタッチ選択でき、透明な穴は選択されない。
- 終了イベント欠落を模した残留ドラッグが、サイズ変更または次のタッチで解除される。
- orientationchange、blur、盤面外のpointerup / pointercancelで解除される。
- タイルの位置・角度・反転・倍率・色は維持される。
- 「次のタイルを選択」が配置を変更せず選択と再描画を更新する。

既存の `browser.cjs`、`color.cjs`、`copy.cjs`、`scheduling.cjs`、`gas-parity.cjs` もすべて成功。画像読み込み、背景削除、マウス／タッチ移動、編集、コピー、PNG画素比較、処理の間引きを確認。

## 実機で確認すること

iPhone Safariでタイル配置後に縦横回転、指を置いたまま回転、回転直後の選択・移動を繰り返す。元の現象が解消するか、選択枠とタッチ位置が一致するかを確認する。iPadでも通常の選択・ドラッグが維持されることを確認する。GASの実際の埋め込み環境での検証は未実施。コミット・push・デプロイはしていない。
