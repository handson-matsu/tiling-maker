# 軽量化の検証（2026-10-08）

公開・commit・push・GASデプロイは未実施。実際の学校でのクラッシュ原因は未特定です。

## 変更

- `app.js` と `gas/index.html` を同一の処理に更新。CSSと画面構成は変更していません。
- 同じ元画像・同じ色のタイルは読み取り専用の色付きCanvasを共有。コピーは参照数を増やすだけで、画像生成も画素走査も行いません。色変更は別のCanvasへ切り替えるので他のコピーには影響しません。
- キャッシュは実際に使われる色だけを保持。最後の参照がなくなった色は削除し、Canvasを0×0にして画素領域を解放可能にします。削除・リセットでも参照を解放します。背景再処理で不要になった未使用の元タイルCanvasも解放します。
- カラーピッカーは1フレーム内の最後の値を処理。コピー・選択変更・保存などの直前には保留色を確定し、操作順序を維持します。
- 盤面描画はrequestAnimationFrameでまとめます。タイル追加・コピー・回転等の状態変更はすべて受け付け、クリック回数を制限しません。
- 背景スライダーは80ms単位に間引きます。操作中もプレビューを更新し、change・次の背景クリック・タイル追加前に最後の値を確定します。「やり直す」は保留処理も取り消します。
- 背景削除の作業画素配列・探索配列を再利用。透明化・色付けの計算式と画像の長辺1400px上限は維持します。
- 写真デコードは同時に1件。連続選択では途中の未着手画像をスキップし、最後の選択だけを反映。描画後のImageとObject URLを解放します。画質やEXIFの扱いを変える別デコーダーには切り替えていません。
- PNG生成用Canvasはエンコード完了後に解放。1200×800、変形、透明部分、白背景は従来通りです。
- 現行両版からアクセスカウンターを削除。
- 旧GAS版を `gas/index.legacy.html` にそのまま保存。旧版には旧カウンターも残っています。比較テストでは外部通信を遮断しています。現行GAS用は `gas/index.html` です。

## 方法と結果

macOSのChrome（headless）で実行。160×120 PNGと、4032×3024のJPEGを使用。JPEGはグラデーション・輪郭を描いた生成画像で、実際のiPad撮影写真ではありません。JPEGは従来通り1400×1050に縮小されます。

1枚に色を付け、回転・反転・拡大後に40回コピー（計41枚）。数値は単回測定の例で、端末・描画タイミングにより変動します。40台同時アクセス試験ではありません。

| 入力 / 指標 | 旧版 | 改善後Pages | 改善後GAS HTML |
|---|---:|---:|---:|
| 軽量画像：保持する色付きCanvas数 | 41 | 1 | 1 |
| 軽量画像：色付き画素領域 | 3.15 MB | 0.077 MB | 0.077 MB |
| 軽量画像：40コピー同期処理 | 7.2 ms | 0.4 ms | 0.3 ms |
| 高解像度：保持する色付きCanvas数 | 41 | 1 | 1 |
| 高解像度：色付き画素領域 | 241.08 MB | 5.88 MB | 5.88 MB |
| 高解像度：40コピー同期処理 | 359.8 ms | 0.5 ms | 0.3 ms |
| 高解像度：40コピー後、2フレーム待機まで | 361.2 ms | 21.3 ms | 1.4 ms |

| 高解像度：読み込み待ち時間 | 64.2 ms | 67.6 ms | 65.9 ms |

MBは10進数。メモリーの値は共有を考慮したCanvasの幅×高さ×4の合計で、Safari/Chrome全体の実RSSやGPUメモリー、元画像・一時配列の総量ではありません。ネイティブメモリーの実測はしていません。新旧で同期描画／遅延描画が異なるため、同期処理時間のみを最終表示速度と解釈しないでください。読み込み単体の高速化は確認できていません。

- 2種の画像で、旧版と改善両版の元画像画素・色付き画像画素・背景削除結果・盤面のハッシュが一致。実際に保存したPNGもSHA-256が一致。
- 改善両版で追加500コピー、100色入力を連続実行。コピー数は欠落せず、共有を維持。最後の色をコピーが引き継ぎ、元の色への復元と他タイルの独立性を確認。リセット後は色キャッシュが空になることを確認。
- 連続スライダー操作中にも複数回プレビューを更新し、やり直し後に古い処理が走らないことを確認。
- 100回のドラッグ移動イベントを1回の描画へ集約し、最後の座標を保持。
- 写真3枚の短時間選択では、最大同時デコード数1、途中の1枚を省略し最後の画像を表示。
- 既存の画像読み込み・Flood Fill・タッチ移動・回転・反転・拡大縮小・色・コピー・削除・リセット・日時付きPNG保存テストを通過。
- 現行両版のJavaScript/CSS一致と、外部通信が発生しないことを確認。

測定生データ：`performance-results.json`。画素照合では元のCanvasを直接読み戻すことによるChromeの描画経路変更を避け、検証用Canvasを経由して取得しています。

## 再実行

Node.js、Playwright、Chromeが必要です。アプリ自体にはこれらは不要です。

```sh
node tests/browser.cjs
node tests/color.cjs
node tests/copy.cjs
node tests/gas-parity.cjs
node tests/scheduling.cjs
node tests/performance.cjs
```

性能テストの測定JSONは `/private/tmp/tiling-performance.json` に出力します。`docs/performance-results.json` は今回測定の保存版です。

## 残るリスクとiPad確認

- 実iPad Safari、実GASのiframe、40人の授業環境は未検証。今回のGAS比較は保存されたHTMLをローカルChromeで開いたものです。
- 1枚の高解像度写真を縮小前にデコードするピークは残ります。画質と旧版の画素結果を維持するため、強制的な低解像度化は行っていません。
- 異なる色を大量に使うと、その種類だけCanvasが必要です。多数の異なる元写真・大量のタイルによる描画負荷も無制限には抑えられません。
- 同一フレームを越えた色変更やプリセットの交互連打では、使用されなくなった色は作り直します。未使用色を無制限にキャッシュすることは避けています。
- 1回の背景処理・色計算は引き続きメインスレッドで同期実行します。遅い端末では一時的な引っかかりが残る可能性があります。
- Canvasを解放可能にしてもOSへのメモリー返却の時期はブラウザ次第です。クラッシュ防止を保証するものではありません。

実機では、実際の撮影JPEG/HEIC（向きも含む）、連続写真選択、色付きコピー連打、背景スライダーと即時追加、長時間の削除・再追加、GAS上のPNG保存を確認してください。画面と保存画像の一致、Safari終了やページ再読み込みの有無を記録し、少人数から授業規模へ広げて確認する必要があります。
